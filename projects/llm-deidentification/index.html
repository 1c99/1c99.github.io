PHI De-Identification Pipeline

Medical images and documents contain PHI embedded in multiple modalities: burned-in text on images, DICOM metadata, PDF documents, and handwritten annotations. Manual de-identification is time-consuming and error-prone.

Two-Pronged Approach

📄 Metadata Anonymization
LLM parses DICOM headers to identify PHI fields (Patient Name, ID, Birth Date) and generates consistent anonymized mappings while preserving non-PHI metadata.
🖼️ Burn-in Text Detection
OCR extracts text regions with bounding boxes. LLM/NER classifies each as PHI or non-PHI. Pixel-level black mask applied over PHI while preserving markers (L/R, PA).

Multilingual Translation System

International regulatory submissions require accurate, consistent translation of medical documents. LLM-based translation can suffer from hallucinations that introduce dangerous inaccuracies — so quality assurance is built into every layer.

English → Japanese Chinese Arabic Spanish French Portuguese Russian

Three Translation Approaches

1
Distributed Ollama + Ray
Load-balanced distribution across multiple Ollama endpoints with async I/O for high throughput batch translation.
2
Multi-Agent Workflow
4 specialized AI agents (Translator → Reviewer → Fixer → Supervisor) mimicking professional translation teams with glossary enforcement.
3
M2M100 + Caching
Facebook’s M2M100 model with SQLite translation cache and HTML-aware processing for structured content.

Quality Assurance

Translation Memory
SQLite-based persistent cache reduces API costs and ensures terminology consistency across documents.
Medical Glossary
Domain-specific terminology enforcement ensures correct translations of anatomical and clinical terms.
Hallucination Detection
Statistical checks for numerical consistency, entity preservation, and semantic alignment.
HTML Preservation
Markup tags preserved during translation of structured content for direct use in submissions.
